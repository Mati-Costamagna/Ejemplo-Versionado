# Checklist de buenas prácticas

Copiar esta lista en el README del repositorio del equipo.

## Todos los días

- [ ] Empiezo con `git pull` antes de tocar cualquier archivo.
- [ ] Uso `git status` cada vez que dudo de en qué estado está algo.
- [ ] Hago `git push` antes de cerrar la computadora.

## Commits

- [ ] Un commit = un cambio con sentido.
- [ ] Mensaje con tipo (`feat`, `fix`, `docs`, `sim`, `chore`), en presente, una línea.
- [ ] Nada de `cambios`, `asd`, `ahora sí`.
- [ ] Menciono el issue cuando corresponde: `(#7)` o `closes #7`.

## Repositorio

- [ ] El README explica qué es el proyecto y cómo se corre.
- [ ] El `.gitignore` está antes del primer commit de código.
- [ ] No hay archivos generados (`.hex`, `build/`) versionados.
- [ ] Los binarios de Proteus se avisan antes de editarlos.

## Issues y tablero

- [ ] Toda tarea tiene su issue antes de empezar a programarla.
- [ ] El issue tiene responsable, etiqueta y criterios de aceptación.
- [ ] Muevo la tarjeta a *En progreso* cuando empiezo, no cuando termino.
- [ ] Cierro el issue solo cuando se cumplen todos los criterios.
